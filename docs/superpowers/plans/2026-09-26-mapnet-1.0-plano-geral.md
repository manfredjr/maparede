# Plano da versão 1.0: portas, identificação, classificação e relatório

Desenho em `docs/superpowers/specs/2026-09-25-mapnet-design.md`, seções 7 a 9. A versão 0.2 (painel do técnico) está publicada na v0.2.5. A versão 1.0 fecha o que o desenho original pediu: saber, além de IP, MAC, fabricante e nome, quais portas comuns cada equipamento tem abertas, o que ele diz de si e de que tipo ele provavelmente é.

## Fatias

| Fatia | Versão | Conteúdo |
|---|---|---|
| 7 | 0.3.0 | Portas TCP comuns abertas, com lista configurável |
| 8 | 0.4.0 | Identificação leve: título HTTP, banner SSH e FTP, certificado HTTPS, UPnP/SSDP |
| 9 | 0.5.0 | Classificação por heurística: roteador, switch, impressora, câmera ou NVR, servidor e estação Windows, Linux ou NAS, access point, celular, IoT, desconhecido |
| 10 | 1.0.0 | Relatório em XML e CSV, além do HTML, pela janela e pela linha de comando |

Cada fatia tem o seu PR, com o plano detalhado antes do código. O plano da fatia 7 vai abaixo. Os das fatias 8 a 10 entram no começo de cada uma.

## Antes da fatia 7: enquadramento jurídico

Olhar portas é o passo em que o programa deixa de só registrar o que a rede mostra sozinha e passa a perguntar a cada equipamento. Continua sem testar senha nem explorar falha, mas o técnico precisa ter a autorização do responsável pela rede. A pendência "Enquadramento jurídico inicial" (`pendencias.md`) cobre isso: papel da MT na LGPD, forma da autorização, aviso ao cliente, guarda e descarte do relatório. A recomendação é fechar essa análise com a `legal-br` antes de publicar a 0.3.0, para a tela e a página já saírem com o aviso certo.

## Fatia 7: portas TCP comuns

### O que entra

- **Sondagem por conexão TCP.** Para cada host encontrado, o programa abre e fecha a conexão em cada porta da lista, sem mandar nenhum dado. Porta que aceita é "aberta". Porta que recusa ou não responde no tempo limite fica de fora. Não pede administrador.
- **Lista padrão**, com o serviço de cada porta:

| Porta | Serviço |
|---|---|
| 21 | FTP |
| 22 | SSH |
| 23 | Telnet |
| 25 | SMTP |
| 53 | DNS |
| 80 | HTTP |
| 135 | RPC do Windows |
| 139 | NetBIOS |
| 443 | HTTPS |
| 445 | Compartilhamento do Windows (SMB) |
| 515 | Impressão LPD |
| 554 | Câmera (RTSP) |
| 631 | Impressão IPP |
| 1433 | SQL Server |
| 3306 | MySQL |
| 3389 | Área de trabalho remota |
| 5000 | NAS e UPnP |
| 5900 | VNC |
| 8000 | HTTP alternativo e NVR |
| 8080 | HTTP alternativo |
| 8291 | MikroTik Winbox |
| 8443 | HTTPS alternativo |
| 9100 | Impressão direta (JetDirect) |
| 37777 | NVR Dahua |

- **Lista configurável** pela linha de comando (`--portas 22,80,443`) e por um campo na janela. Porta fora de 1 a 65535 é recusada.
- **Onde aparece:** coluna "Portas" na tabela (números separados por vírgula, com o serviço na dica), bloco "Portas abertas" no detalhe do host, com atalho para abrir no navegador as portas web, e coluna no relatório HTML.
- **Desligável:** caixa "Olhar portas" na janela e `--sem-portas` na linha de comando, para uma varredura só de descoberta.

### Regras

- **Só conectar e fechar.** Nenhum byte enviado. Banner e título ficam para a fatia 8.
- **Limites:** no máximo 128 conexões ao mesmo tempo no total e 8 por host, com 800 ms de tempo limite por porta. Uma sub-rede /24 com 20 hosts e 24 portas termina em poucos segundos.
- **Só a sub-rede varrida.** A sondagem de portas usa a mesma lista de hosts da descoberta. Nunca sai dela.
- **Cancelar vale para tudo.** O botão Cancelar para também a etapa de portas.

### Arquitetura

- `src/mapnet.nucleo/portas/`: `ListaPortas` (padrão, interpretação de `--portas` e nome do serviço), `ISondaPorta` com `SondaPortaTcp` (conexão com tempo limite) e a etapa `Portas` do `Varredor`, com andamento na barra de estado.
- `HostEncontrado.PortasAbertas` e texto pronto para a tabela, o detalhe e o relatório.
- Janela: coluna, bloco no detalhe, campo da lista e caixa para desligar. Linha de comando: `--portas` e `--sem-portas`.

### Testes

1. Interpretação de `--portas`: lista válida, repetida, fora do intervalo, com texto e vazia.
2. A etapa de portas só sonda os hosts da descoberta e respeita os limites de conexões (sonda simulada que conta as conexões ao mesmo tempo).
3. Cancelar para a etapa de portas.
4. Tabela, detalhe e relatório mostram as portas, com o serviço, e o relatório codifica o texto.
5. Modo de demonstração com portas de exemplo, para as imagens.

### Como testar

1. Varrer a rede de teste com as portas ligadas e conferir, no roteador, a porta 80 ou 443; numa impressora, a 9100; num Windows com compartilhamento, a 445.
2. Varrer de novo com `--sem-portas` e ver que a coluna fica vazia.
3. Rodar `mapnet --varrer --portas 22,80` e conferir o relatório.
